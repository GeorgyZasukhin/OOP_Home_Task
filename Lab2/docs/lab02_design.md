# Проєктування класу Performance

Варіант 9 у методичці лабораторної №2 — квитковий облік театру.

## Операції

- Прочитати та змінити назву вистави і режисера.
- Прочитати та змінити дату прем'єри після перевірки календаря.
- Установити місткість залу, не скасовуючи вже продані місця.
- Продати один квиток, якщо залишилися місця.
- Повернути один квиток, якщо є продані квитки.
- Обчислити кількість вільних місць і визначити, чи зал заповнений.

## Необхідні поля

- `title_`, `std::string` — назва для ідентифікації вистави.
- `director_`, `std::string` — режисер для показу відомостей.
- `premiereDate_`, `std::string` — дата для відомостей і перевірки формату.
- `totalSeats_`, `int` — місткість для обмеження продажів.
- `soldTickets_`, `int` — кількість продажів для продажу та повернення.

`freeSeats()` обчислюється як місткість мінус продажі. `isSoldOut()`
визначається за нульовим залишком. Ці значення не зберігаються в полях.

## Інваріант

1. Назва порожня для чернетки або містить непробільний символ.
2. Ім'я режисера порожнє або містить непробільний символ.
3. Дата порожня або є реальною датою у форматі YYYY-MM-DD.
4. Загальна кількість місць невід'ємна.
5. Зв'язок полів: `0 <= soldTickets_ <= totalSeats_`.

Власного конструктора немає: ця тема належить наступній лабораторній.
Початковий стан — порожня чернетка з нульовими лічильниками. Порожні
рядки допустимі саме як незаповнені поля; сетери відхиляють порожнє
введення. Продаж залежить від лічильників місць і квитків, а не від
заповненості опису. Чернетка без місць має `isSoldOut() == true`, тобто
не має місць для продажу. Розклад сеансів і персональні квитки до обсягу
цього класу не входять.

## Захист стану

Усі перевірки виконуються до присвоєння. Методи зміни повертають `bool`.
Окремого сетера проданих квитків немає: є `sellTicket()` і
`returnTicket()`. Місткість не може стати меншою за кількість продажів.
Статичний `isValidDate()` перевіряє формат і григоріанський календар
у діапазоні років 0001–9999; минулі й майбутні дати дозволені.
Пробільні символи для назви та режисера — звичайні ASCII-пробіли,
табуляція і переведення рядка; нормалізація Unicode не реалізується.

Приватний `checkInvariant()` повторює п'ять умов. Тестовий адаптер
`PerformanceTestAccess` оголошений другом класу й використовується
лише для виклику цієї перевірки. У робочому інтерфейсі метод не відкритий.

## Виправлена помилка

Початкова перевірка високосності використовувала лише `year % 4 == 0`.
Тест `case_5` виявив, що 1900-02-29 та 2100-02-29 помилково приймалися.
Правило виправлено: рік ділиться на 400 або ділиться на 4, але не на 100.
Після виправлення всі 15 тестів пройшли.
